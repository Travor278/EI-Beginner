# Diffusion Policy 后续研究方向规划

## 适用前提

这份规划基于当前现实约束：

- 无真机，主要依赖仿真；
- 单卡 `RTX 5070 Laptop GPU`，显存约 `8 GB`；
- 已有 `robodiff` 参考环境和 `robodiff-gpu` 现代 GPU 环境；
- 希望在 `Diffusion Policy` 复现基础上升级；
- 优先考虑 `training-free`、`test-time`、`小模型辅助模块`、`adapter-only` 这类低算力路线；
- 目标不是只“做个工程技巧”，而是保留足够论文味和实验空间。

## 默认主线

这是我建议的默认推进顺序，也是后面最稳的开题路径：

1. 先把 `Diffusion Policy` baseline 复现到能跑 `Push-T` 或一个 `robomimic / LIBERO` 小任务；
2. 然后优先做 `A + C` 融合版，也就是：
   - 不改主 policy；
   - 增加 `progress / failure predictor`；
   - 先做 `test-time guidance`；
3. 先跑出比 baseline 更稳的：
   - success rate
   - recovery rate
   - long-horizon success
4. 如果这条线跑顺了，再决定要不要继续往：
   - 语言条件
   - memory
   - encoder upgrade
   扩展。

一句话总结：

**先做最便宜、最容易出结果、也最有文章感的方向，再从那里分叉。**

## 近作筛选后的判断

我重点看了几类与你最相关的近作：

| 方向 | 代表工作 | 对我们的启发 |
|---|---|---|
| 进度建模 | `ProgressVLA` (2026-03) | `progress` 是真实缺口，但原方案偏重，需要 progress estimator + world model |
| 测试时引导 | `PPGuide` (2026-03), `OmniGuide` (2026-03), `ACG` (2025-10) | 说明“冻结主策略，在推理时加引导”非常适合低算力路线 |
| 闭环校验 / 自校正 | `SV-VLA` (2026-04), `AnchorVLA` (2026-04) | 长 action chunk 容易漂，轻量 verifier / residual correction 很有用 |
| 长时程记忆 | `RMBench` (2026), `VQ-Memory / RuleSafe` (2026-03), `SOMA` (2026-03) | `memory` 是很新的切口，但 benchmark 和系统设计更难 |
| 编码器升级 | `Compression Gap` (2026-04) | 连续动作策略比离散 token VLA 更吃 encoder scaling，这对 Diffusion Policy 很重要 |
| 推理效率 | `AAC` (2026-04), `SnapFlow` (2026-04) | 这条线很新，但已经开始变拥挤，而且容易做成“工程优化”而不是核心研究问题 |

基于这些文献，我最后不建议把方向铺得太散，而是保留最能做文章的三条：

1. `Progress / Failure-aware Test-Time Guidance`
2. `Memory-lite Diffusion Policy`
3. `Encoder-upgraded Continuous-Action Diffusion Policy`

## 最终保留的三个方向

### 方向 1：Progress / Failure-aware Test-Time Guidance

推荐指数：`最高`

一句话题目：

**面向长时程操作的进度与失败预测测试时引导扩散策略**

### 核心想法

先复现一个标准 `Diffusion Policy`，然后不大改主网络，只额外训练一个很小的 `predictor`，在推理时对采样动作做引导。

最直接的实现可以是：

- `progress predictor`：判断当前 rollout 离成功还有多远；
- `failure predictor`：判断当前 observation-action chunk 是否正走向失败；
- `test-time guidance`：在 diffusion 采样时，用这两个 predictor 提供额外梯度或重打分；
- `optional verifier`：只在“怀疑出错”时触发额外校验，而不是每一步都重规划。

### 为什么这条线最适合你

- 不需要重训大模型；
- 不需要真机；
- 很适合仿真 benchmark；
- 和你原本的 `A + C` 融合版完全一致；
- 最近确实有趋势支撑，但还没被做烂。

### 创新点

如果按你的资源做，我建议把创新写在这三个点上：

1. **统一 progress 与 failure 两种信号**
   现在很多工作只做成功概率、只做进度、或只做外部 guidance；把二者合起来会更像“恢复能力”而不是单纯“更会做”。

2. **不依赖重型 world model**
   相比 `ProgressVLA` 那类需要更复杂链路的方法，我们可以刻意保持“轻预测器 + 测试时引导”路线，突出低算力和可插拔性。

3. **面向长时程失败恢复**
   指标不只看总成功率，还看：
   - 偏离后能否回正；
   - action chunk 出错后的恢复速度；
   - long-horizon task 中后段的成功保持率。

### 风险

1. predictor 信号可能太弱，指导不了主策略。
2. 只做 guidance，增益可能不如重训式方法大。
3. 如果 benchmark 太短，progress 优势不明显。

### 降风险建议

1. 先选本来就容易“后程失误”的任务，不要一开始只盯短程 pick-place。
2. 先做 `failure-only` 或 `progress-only` 消融，再做组合。
3. 先在 `Push-T + 一个 robomimic / LIBERO 小任务` 验证，再扩长时程任务。

### 算力评估

- 主 policy 可冻结；
- 新增模块可以很小；
- 最适合单卡；
- 是三条路线里最接近 `training-free / low-compute` 的。

### 结论

**这是默认主线。**

### 方向 2：Memory-lite Diffusion Policy

推荐指数：`高`

一句话题目：

**面向非马尔可夫桌面操作的轻量记忆增强扩散策略**

### 核心想法

不做重型 recurrent world model，而是做“够用但可解释”的轻量记忆：

- 历史帧堆叠
- 检索式 episodic memory
- compact memory token
- VQ memory / summary token

再在需要记忆的任务上比较这些方法。

### 这个方向为什么值得保留

- `memory-dependent manipulation` 是明显的新热点；
- `RMBench`、`RuleSafe / VQ-Memory`、`SOMA` 都说明“没有记忆的 policy 在长时程和非马尔可夫场景里会掉得很明显”；
- 这条线比普通“加语言”更有研究味。

### 最适合你的版本

不要一开始做“超大 memory system”，而是做：

1. baseline `Diffusion Policy`
2. `frame stack`
3. `retrieval memory`
4. `compact memory token`

然后在人为构造的非马尔可夫任务上比：

- 遮挡后重现目标
- 目标临时离开视野
- 指令引用过去对象
- 子任务切换需要记住历史状态

### 创新点

1. **记忆触发式而非常驻式**
   只有当“当前 observation 不足以决策”时才调用 memory，而不是全程重 memory。

2. **外部 memory 优先，少动主策略**
   更符合单卡路线，也更容易解释“到底是记忆在起作用，还是模型容量变大了”。

3. **面向 manipulation 的记忆消融协议**
   论文价值不只是方法，也可以来自清楚的 benchmark 设计和误差拆解。

### 风险

1. 如果 benchmark 设计不好，memory 的优势不明显。
2. 很容易做成系统工程，而不是一个清晰的方法贡献。
3. 如果 retrieval / memory 设计太复杂，会偏离“低算力”初衷。

### 降风险建议

1. 先做 `frame stack -> external retrieval -> compact token` 三档。
2. 先用仿真构造小型 non-Markovian benchmark。
3. 指标除了 success，还要加：
   - occlusion recovery
   - delayed reference recall
   - subgoal consistency

### 算力评估

- 比方向 1 略贵，但仍然明显低于重训 VLA；
- 更偏实验设计与系统拆解，算力压力可控。

### 结论

**这是第二主线，也是最“新”的方向之一。**

### 方向 3：Encoder-upgraded Continuous-Action Diffusion Policy

推荐指数：`中高`

一句话题目：

**面向连续动作扩散策略的参数高效视觉编码器升级**

### 核心想法

基于 `Compression Gap` 的观察，连续动作策略比离散 token VLA 更容易从更强视觉编码器中获益。

最适合你的做法不是“整模重训”，而是：

- 主策略基本冻结；
- 换更强的视觉 encoder；
- 只训练 adapter / projector / 少量 fusion 层；
- 比较不同 encoder 对连续动作 Diffusion Policy 的收益。

### 为什么这条线有潜力

- 有清晰理论和经验趋势支撑；
- 和 Diffusion Policy 的连续动作表征天然匹配；
- 算力上比 full finetune 便宜；
- 更像一个“有观点”的研究问题，而不只是堆模块。

### 创新点

1. **把 encoder scaling 明确落到 Diffusion Policy**
   不只是引用 `Compression Gap`，而是做你自己的受限资源验证。

2. **参数高效训练**
   只训练小投影层 / adapter，使路线更贴近单卡现实。

3. **研究“何时值得升级 encoder”**
   不同任务、不同视觉难度、不同动作空间下，收益可能不同，这本身就是论文点。

### 风险

1. 如果数据和任务太小，encoder 升级收益可能不稳定。
2. 它的“文章感”比方向 1 和方向 2 更依赖实验设计，而不是一个新机制。
3. 容易做成“某个 backbone 更强”的经验报告。

### 降风险建议

1. 不要只比成功率，要比：
   - sample efficiency
   - OOD generalization
   - visual perturbation robustness
2. 保持主 policy 尽量不变，把变量控制住。
3. 至少比较两种强 encoder 和一个轻 encoder。

### 算力评估

- 明显低于 full finetune；
- 高于方向 1；
- 在单卡上仍可做，但要控制实验规模。

### 结论

**这是第三主线，适合作为“有理论依据的低算力升级路线”。**

## 为什么不把其他方向放进前三

### 不保留：纯 Spatially-grounded / 多辅助监督路线

原因：

- 需要更多 teacher / segmentation / depth / pose 辅助信号；
- 工程量大；
- 更容易把工作做散；
- 以你现在的资源，不如前三条集中。

### 不保留：纯推理效率路线

例如：

- `AAC`
- `SnapFlow`
- `AnchorVLA`
- `SV-VLA`

这些工作都很新，但已经开始变拥挤，而且更容易被审稿人理解成“部署优化”而不是主要科学问题。  
当然，它们很适合作为方向 1 的技术组件，而不是单独作为你的主线。

## 最终排序

### 默认推荐排序

1. `方向 1：Progress / Failure-aware Test-Time Guidance`
2. `方向 2：Memory-lite Diffusion Policy`
3. `方向 3：Encoder-upgraded Continuous-Action Diffusion Policy`

### 如果你只想先做一篇最稳的

选 `方向 1`。

### 如果你想更“新”一点

选 `方向 2`。

### 如果你想要一个更有观点、和 VLA scaling 接轨的题

选 `方向 3`。

## 我建议的实际执行路径

### Stage 1：先做 baseline

1. 跑通 `Diffusion Policy`
2. 先在 `Push-T` 或一个 `robomimic / LIBERO` 小任务上拿到基线结果
3. 固定训练脚本和评测协议

### Stage 2：默认进入方向 1

1. 加 `failure predictor`
2. 做 `test-time guidance`
3. 再加 `progress predictor`
4. 做组合 guidance
5. 把 long-horizon / recovery 指标补齐

### Stage 3：如果方向 1 有效果，再分叉

- 想更前沿：转方向 2
- 想更稳、更易写清楚：转方向 3
