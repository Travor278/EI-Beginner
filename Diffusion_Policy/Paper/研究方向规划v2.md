# Diffusion Policy 研究方向规划 v2（二次审查修订版）

## 为什么需要 v2

v1 中最推荐的三个方向在经过**两轮系统性文献审查**后，均发现存在严重的新颖性问题：

| v1 方向 | 审查结论 | 致命竞品 |
|---|---|---|
| 方向1: Progress/Failure-aware Test-Time Guidance | **赛道饱和，放弃** | VLS, VLA-Pilot, OmniGuide, PPGuide, ACG, Update-Free Steering, CoVer-VLA 等 6-8 篇直接覆盖 |
| 方向2: Memory-lite Diffusion Policy | **竞品较多** | EchoVLA, SAM2Act+, SOMA, VQ-Memory |
| 方向3: Encoder-upgraded DP | **部分覆盖** | DINOv3-DP, Compression Gap |

此外，我们中间探索的两个候选方向也被否决：

| 中间候选 | 审查结论 | 致命竞品 |
|---|---|---|
| Foundation-Grounded Guidance（DINOv2/SAM2引导DP） | **核心思路被DynaGuide覆盖** | DynaGuide (NeurIPS 2025): 完全相同的 DINOv2 + DP guidance 框架 |
| Uncertainty-Adaptive Execution（采样方差自适应chunk长度） | **多个竞品** | D3P (动态denoising步数), MoH (自截断chunk), Diff-DAgger (不确定性度量), AdaEnt (entropy早停) |

**核心发现**：Diffusion Policy 的 "Test-Time / Training-Free / Adaptive" 赛道在 2025-2026 已**全面饱和**。

## 赛道饱和全景图

```
Test-Time Guidance/Adaptation 赛道（2025-2026，已饱和）
├── VLM 语言 reward 引导        → VLS, VLA-Pilot, PLARE
├── 3D/空间 FM 引导             → OmniGuide
├── 视觉 latent dynamics 引导   → DynaGuide (DINOv2, NeurIPS 2025)
├── Action coherence 引导       → ACG, BID (ICLR 2025)
├── Trained verifier 选择       → CoVer-VLA, Update-Free Steering
├── Test-time RL               → TT-VLA
├── Policy 分布组合             → Compose Your Policies
├── 隐式 test-time compute      → RD-VLA
├── 自适应去噪步数              → D3P, AdaEnt (ICCV 2025), ADPro
├── 不确定性利用                → "Uncertainty Comes for Free", Diff-DAgger, Sentinel
├── Action chunk 改进           → BID, A2C2, RTC, MoH
└── 检索/记忆                   → STRAP (ICLR 2025), EchoVLA, SAM2Act+
```

## 转向策略

不再在饱和赛道里挤，转向 Diffusion Policy 的**训练侧**未被探索的方向。

经过对四个候选赛道的系统搜索：

| 赛道 | 竞争程度 | 最终判断 |
|---|---|---|
| Data-Efficient DP（少样本高效训练） | 中低 | 有空间，但需要方法贡献 |
| Deformable Object DP（柔性物体操作） | 中低 | 需特殊仿真器，增加环境复杂度 |
| Failure Mode Analysis（失败模式分析） | 低 | 有空间但分析型论文发表风险高 |
| **Curriculum Training for DP** | **极低（空白）** | **无直接竞品，确认可做** |

最终推荐将 **Data-Efficient** 和 **Curriculum** 两个赛道融合。

## 新主线方向：面向小样本场景的课程式扩散策略训练

### 一句话题目

**Curriculum-Driven Data-Efficient Diffusion Policy with Pretrained Visual Backbone**

面向小样本操作场景的课程驱动数据高效扩散策略

### 核心想法

标准 Diffusion Policy 训练将所有示教数据一视同仁地随机打乱训练。我们的核心观察是：

1. **示教数据有难度差异**：短轨迹/直线运动 vs 长轨迹/复杂接触
2. **从易到难的课程训练未被研究**：在 RL 中 curriculum learning 已被广泛验证，但在 Diffusion Policy（监督式行为克隆）中完全空白
3. **预训练视觉 backbone 可以进一步放大课程效果**：DINOv2 的零样本视觉特征在少量数据时提供更好的初始化

```
训练数据
  ↓ 按难度指标排序（轨迹长度 / 动作方差 / 曲率）
  ↓
Phase 1: 只用"简单"示教训练 DP
  ↓
Phase 2: 逐步加入"中等"示教
  ↓
Phase 3: 加入"困难"示教
  ↓
最终 Policy（收敛更快 / 同等数据下更好 / 少数据下可用）
```

### 二次审查：竞品分析

| 工作 | 与我们的关系 | 关键区别 |
|---|---|---|
| DiCuRL (NeurIPS 2024) | 名字最像："Diffusion-based Curriculum RL" | 用扩散模型**生成课程目标**给 RL agent；我们是**对 Diffusion Policy 的训练数据做课程排序**。完全不同的使用方式 |
| Curriculum DPO (2024) | 课程 + 扩散模型 | 针对文本到图像生成的偏好优化；不同领域 |
| Cocos (NeurIPS 2025) | 加速 DP 训练 | 通过修改 conditioning 的 source distribution 加速收敛；**不涉及数据排序或课程** |
| DINOv3-DP (2025-09) | backbone 对比 | 比较 DINOv3 vs ResNet-18；**不涉及课程，不研究少样本** |
| IMLE Policy (2026-02) | 少数据替代方案 | 完全不同的架构（非扩散模型），替代 DP 而不是改进 DP |
| Instant Policy (ICLR 2025 Oral) | 1-shot | In-context learning，图扩散；**完全不同的范式** |
| CurricuLLM (ICRA 2025) | 课程 + 机器人 | 用 LLM 为 RL 设计课程；**RL 而非行为克隆** |
| DemoDiffusion (2025-06) | 1-shot DP | 从人类视频做 one-shot；需要预训练泛化模型 Pi-0 |

**审查结论：无直接竞品。** "Curriculum ordering for Diffusion Policy training" 是一个确认空白的研究问题。

### 创新点

1. **首次将课程学习引入 Diffusion Policy 训练**
   - 定义操作示教的难度度量（轨迹长度、动作方差、路径曲率、子任务数量）
   - 研究不同课程策略（easy-to-hard / hard-to-easy / mixed / anti-curriculum）对收敛和最终性能的影响
   - 提出自适应课程：根据训练 loss 动态调整数据采样权重

2. **预训练视觉 backbone + 课程的协同效应**
   - 冻结 DINOv2-small 作为视觉编码器，只训练 policy head
   - 研究：当 demo 数量从标准量（如 200）逐步减少到 50 → 25 → 10 时，课程 + DINOv2 的组合是否能保持性能
   - 与 ResNet-18 baseline 对比，展示预训练特征在少样本下的优势

3. **系统性的小样本实验协议**
   - 构建清晰的实验矩阵：(backbone: ResNet-18 / DINOv2-small / DINOv2-base) × (curriculum: random / easy-hard / hard-easy / adaptive) × (demo count: 200 / 100 / 50 / 25 / 10)
   - 这个实验矩阵本身就是社区缺失的贡献

### 论文故事线

**Research Question**: 当示教数据有限时，课程式训练和预训练视觉特征能否协同提升 Diffusion Policy 的样本效率？

**Motivation**: 
- 真实机器人示教采集成本高，少样本训练是刚需
- Diffusion Policy 在少样本下性能退化严重（已知问题）
- 课程学习在 RL 中广泛有效，但在 DP 中从未被研究
- 预训练视觉编码器在少数据时应有更大优势，但缺乏系统验证

**Method**:
1. 示教难度度量 → 2. 课程排序策略 → 3. 冻结 DINOv2 backbone → 4. 渐进式训练

**Experiments**:
- Push-T: 快速验证（简单任务，数据量容易控制）
- LIBERO-Spatial / LIBERO-Object: 中等难度，多任务
- LIBERO-Long: 长时程，课程效果应最明显

**Expected Findings**:
- Easy-to-hard 课程 > Random > Hard-to-easy（假设）
- DINOv2 + Curriculum > DINOv2 alone > ResNet + Curriculum（假设）
- 效果差距在 demo 数量越少时越大（假设）

### 适合我们配置的原因

| 约束 | 满足情况 |
|---|---|
| RTX 5070 Laptop 8GB | DINOv2-small 冻结约 300MB；DP 训练在小数据集上 < 4GB；完全够用 |
| 无真机 | 全部仿真实验（Push-T / LIBERO） |
| 低算力路线 | 冻结 backbone + 小数据集 = 每次训练 < 1 小时 |
| 论文味 | 有清晰 research question + 系统实验矩阵 + 首次研究 |

### 风险与降风险

| 风险 | 概率 | 降风险措施 |
|---|---|---|
| 课程排序对 DP 没有明显效果 | 中 | 1) 选本来就对训练顺序敏感的长时程任务；2) 即使效果小，"首次研究 + negative result analysis"也有发表价值；3) 可以加入自适应采样权重强化效果 |
| 难度度量设计不好 | 中低 | 提出多个度量（长度/方差/曲率），比较它们，本身就是贡献 |
| DINOv2 在仿真渲染上效果不如预期 | 低 | DINOv3-DP 已验证冻结 DINOv3 在仿真中有效；DINOv2 也有类似结论 |
| 实验矩阵太大跑不完 | 中 | 分优先级：先做 Push-T 上的 core ablation（2×3×3=18 实验），再扩展到 LIBERO |

### 示教难度度量候选

| 度量 | 计算方式 | 直觉 |
|---|---|---|
| 轨迹长度 | action chunk 总步数 | 短任务更简单 |
| 动作方差 | action sequence 的 per-step 方差均值 | 方差小 = 运动更平稳 = 更简单 |
| 路径曲率 | 末端执行器轨迹的平均曲率 | 曲率小 = 接近直线 = 更简单 |
| 回放成功率 | 在仿真中回放该示教的成功率 | 直接度量质量，但需要仿真回放 |
| 多模态程度 | 同一初始状态下不同示教的分歧度 | 分歧小 = 策略更确定 = 更简单 |

### 与 Cocos 的关系

Cocos (NeurIPS 2025) 通过修改 flow matching 的 source distribution 加速 DP 训练。我们的方法是正交的：

- Cocos 改的是**训练目标**（conditioning 方式）
- 我们改的是**训练数据呈现顺序**（curriculum）
- 两者可以叠加使用
- 在论文中可以做 "ours + Cocos" 的组合消融，进一步增强结果

## 备选方向：Diffusion Policy 失败模式系统研究

### 一句话题目

**When Does Diffusion Policy Fail? A Controlled Diagnostic Study**

扩散策略何时失败？一个受控诊断研究

### 核心想法

当前社区对 Diffusion Policy 的失败模式缺乏系统理解。Sentinel (CoRL 2024) 做了运行时失败检测，但**没有回答"为什么失败"和"如何在训练时预防"**。

我们的研究：
1. 系统性地构造导致 DP 失败的受控场景
2. 建立失败模式分类法（taxonomy）
3. 对每种失败模式提出针对性的轻量训练改进
4. 发布一个诊断性 benchmark

### 候选失败模式分类

| 失败类别 | 具体表现 | 如何受控构造 |
|---|---|---|
| **后程漂移** | 长时程任务后半段成功率骤降 | 设计 5-step 以上的串联子任务 |
| **多模态崩溃** | 示教数据有多种解法时策略退化为平均 | 同一任务提供两种截然不同的示教路径 |
| **遮挡敏感** | 目标物体被短暂遮挡后策略失效 | 在仿真中插入遮挡物 |
| **干扰脆弱** | 轻微外力干扰后无法恢复 | 在 rollout 中注入随机位移 |
| **分布外退化** | 初始状态偏离训练分布时性能崩塌 | 系统性偏移初始位置/角度 |

### 二次审查

| 竞品 | 区别 |
|---|---|
| Sentinel (CoRL 2024) | 做失败**检测**，不做失败**分析和预防** |
| MoE-DP (2025-11) | 用 MoE 解决 failure recovery，但不做系统分析 |
| 各类 Survey | 提供方法分类法，不提供失败分类法 |
| Demystifying DP (CoRL 2025 Workshop) | 分析 action chunking 的数学性质，不做失败诊断 |

**审查结论：无直接竞品。** "DP 失败模式系统研究"是空白。

### 为什么是备选而非主线

1. 分析型论文发表难度更高（审稿人可能要求更强的方法贡献）
2. 实验设计需要更多经验（知道什么实验能说明什么问题）
3. 对初学者来说，"做一个系统研究"比"做一个具体方法"更难把握完成度

### 但它可以和主线融合

如果主线方向（课程训练）的课程效果不够强，可以转为：

**"通过失败分析驱动的针对性课程训练"**

即：先分析 DP 失败模式 → 构造专门针对这些失败的训练数据 → 用课程式训练重点补强薄弱环节。

这比纯课程或纯分析都更有故事性。

## 最终排序

| 排序 | 方向 | 新颖性 | 可行性 | 8GB可做 | 适合初学者 |
|---|---|---|---|---|---|
| **主线** | 课程式小样本 DP（含 DINOv2 backbone） | 高（空白赛道） | 高 | 是 | 是 |
| **备选** | DP 失败模式诊断研究 | 高（空白赛道） | 中 | 是 | 中 |
| **融合** | 失败驱动的课程训练 | 极高 | 中 | 是 | 中 |

## 执行路径

### Stage 1：Baseline（与 v1 一致）

1. 在 `robodiff-gpu` 中跑通 Diffusion Policy
2. 在 Push-T 上拿到基线结果
3. 固定训练脚本和评测协议

### Stage 2：课程实验（Push-T）

1. 收集 Push-T 示教数据，计算各条示教的难度指标
2. 实现课程数据加载器（按难度排序 / 随机 / 反序）
3. 在标准数据量下对比：random vs easy-to-hard vs hard-to-easy
4. 验证课程效果是否存在

### Stage 3：加入 DINOv2 backbone

1. 将 ResNet-18 替换为冻结 DINOv2-small
2. 重跑 Stage 2 的课程实验
3. 对比 backbone × curriculum 的交互效应

### Stage 4：少样本实验

1. 将 demo 数量从 200 逐步削减到 100 / 50 / 25 / 10
2. 在每个数据量下对比 (backbone × curriculum) 组合
3. 画出 sample efficiency 曲线

### Stage 5：扩展到 LIBERO

1. 选 LIBERO-Spatial 或 LIBERO-Long
2. 重复 Stage 2-4 的核心实验
3. 验证结论是否跨任务迁移

### Stage 6（可选）：失败分析 + 针对性课程

1. 在 Stage 4 中找到 DP 失败最严重的场景
2. 构造诊断任务
3. 用针对性课程补强
