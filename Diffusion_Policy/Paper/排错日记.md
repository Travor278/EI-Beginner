## 排错记录

| 编号 | 问题 | 现象 | 根因 | 处理 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 1 | 官方老环境不适配当前 GPU | `pytorch=1.12.1 + cudatoolkit=11.6` 能看到 GPU，但 CUDA 运算不稳定 | 官方环境太旧，不适配当前显卡架构 | 新建 `robodiff-gpu`，改用现代 `PyTorch/CUDA` 组合 | 新环境可稳定使用 CUDA |
| 2 | GitHub 仓库直连不稳定 | `git clone` / `git ls-remote` 在 WSL 中经常超时 | WSL 直连 GitHub 不稳定 | 改用 GitHub codeload 压缩包下载源码 | 官方代码成功落到 `/home/Travor/workspaces/diffusion_policy` |
| 3 | 最小依赖不完整 | `Push-T` 导入链一路缺包 | 只装了 PyTorch 和少量基础包 | 按最小链路逐层补 `zarr`、`hydra-core`、`pygame`、`pymunk`、`shapely`、`diffusers`、`pandas`、`robomimic` 等 | 依赖链逐步补齐 |
| 4 | `gym==0.21.0` 安装失败 | 在当前 `pip` / `Python 3.10` 上构建失败 | 官方依赖锁在老版本 `gym` | 暂时切到 `gym==0.23.1` | 训练链路得以继续，但引出新版 Gym 接口兼容问题 |
| 5 | `numpy` 和 `scikit-image` ABI 冲突 | `ValueError: numpy.dtype size changed` | `numpy 2.2.6` 与 `scikit-image 0.19.3` 二进制不兼容 | 固定为 `numpy=1.26.4`、`scikit-image=0.19.3` | `skimage.transform` 可正常导入 |
| 6 | `diffusers` 与 `huggingface_hub` 不兼容 | `ImportError: cannot import name 'HfFolder'` | `diffusers==0.11.1` 依赖旧版 Hub 接口 | 回退为 `huggingface_hub==0.12.1` | `diffusers` 调度器可正常导入 |
| 7 | `robomimic` 缺失 | 训练 image policy 时提示 `No module named 'robomimic'` | `DiffusionUnetHybridImagePolicy` 复用了 `robomimic` 编码器与配置工具 | 安装 `robomimic==0.2.0` | `robomimic + policy` 导入通过 |
| 8 | `pandas` 缺失 | workspace 导入时报 `No module named 'pandas'` | `JsonLogger` 直接依赖 `pandas` | 安装 `pandas` | workspace 导入通过 |
| 9 | `wandb` 新 key 与旧客户端冲突 | 新 key 为 `wandb_v1_...`，旧 CLI 报 `API key must be 40 characters long` | 旧版 `wandb` 仍按老格式校验 key | 先统一用 `logging.mode=offline`，后续升级客户端 | 当前训练可离线记录，在线模式仍单独排查 |
| 10 | WSL 直连下载数据不稳定 | `pusht.zip` 中途断掉，只留下半截文件 | WSL 对数据源连接不稳定 | 改用 Windows 侧直连下载，再复制回 WSL | 数据完整解压，半截 zip 和中转文件已清理 |
| 11 | `numba / llvmlite` 与 `libstdc++` 冲突 | `CXXABI_1.3.15 not found`、`libllvmlite.so` 无法加载 | 运行时优先加载了系统侧旧 `libstdc++.so.6` | 重新激活 conda 环境并使用环境内动态库 | `PushTImageDataset` 可稳定读取，`len = 10726` |
| 12 | `AsyncVectorEnv(shared_memory=True)` 与新版 Gym 不兼容 | 报 `incompatible with non-standard Gym observation spaces` | 新版 Gym 下共享内存 batching 不兼容当前观测结构 | 修改 [pusht_image_runner.py](/home/Travor/workspaces/diffusion_policy/diffusion_policy/env_runner/pusht_image_runner.py)，加入 `shared_memory=False` 并向下传参 | 绕开共享内存路径，训练继续推进 |
| 13 | `reset_async / reset_wait` 接口不兼容 | 报 `unexpected keyword argument 'seed'` | 仓库里的 `AsyncVectorEnv` 仍按旧 Gym API 编写 | 修改 [async_vector_env.py](/home/Travor/workspaces/diffusion_policy/diffusion_policy/gym_util/async_vector_env.py)，兼容 `seed`、`return_info`、`options` | 训练越过 `reset` 阶段 |
| 14 | `concatenate(...)` 参数顺序不兼容 | 在 `reset_wait` / `step_wait` 中触发 `AssertionError` | 新版 Gym 的签名是 `concatenate(space, items, out)` | 继续修改 [async_vector_env.py](/home/Travor/workspaces/diffusion_policy/diffusion_policy/gym_util/async_vector_env.py)，调换 `concatenate(...)` 参数顺序 | `Push-T` rollout 与训练循环最终跑通 |
| 15 | `pred_hardness` 数据集图像维度不对 | `stage3_train_phrew.py` 在 `crop_randomizer` 里报断言 | `Push-T` zarr 里的 `img` 实际是 `HWC`，但 `pred_hardness/dataset.py` 一开始按 `CHW` 直接喂给官方视觉栈 | 改成先 `/255`，再 `np.moveaxis(image, -1, 1)`，让输出和官方 `PushTImageDataset` 一致 | 图像观测成功过掉裁剪与编码器前置检查 |
| 16 | `normalizer` 和模型不在同一设备 | `RuntimeError: Input type (torch.FloatTensor) and weight type (torch.cuda.FloatTensor) should be the same` | `policy` 先 `.to(device)`，之后才 `set_normalizer(...)`，导致新挂进去的 normalizer 留在 CPU | 改成先 `set_normalizer(normalizer)`，再统一 `policy.to(device)` | `compute_loss` 不再因为 CPU/GPU 混用直接报错 |
| 17 | 烟测看起来像“卡住” | `stage3` 的 2-epoch smoke 十几分钟没有新输出 | 这不是单纯 import check，而是完整训练 + rollout；同时用户中断后的 `stage3_train_phrew.py` 进程还留在 WSL 后台继续跑，占着 GPU | 明确把 smoke 视作小规模真训练；下次先查 `ps` 和 `logs.json.txt`，必要时先 `kill` 残留进程再重跑 | 后续可按更可控的手动命令来单独跑 `stage2b` 和 `stage3` |
| 18 | `seed` 和 hardness 文件不匹配 | `AssertionError: hardness_scores length ... != dataset size ...` | `stage2b_score_chunks.py` 的 train split 受 `seed` 影响，`seed=42` 生成的 `chunk_hardness_norm.npy` 不能直接给 `seed=43` 的训练集用 | 每个 seed 单独生成一份 hardness 文件，例如 `artifacts/phrew_seed43/chunk_hardness_norm.npy` | `uniform_seed43` 和 `soft_hard_seed43` 可正常起跑 |
| 19 | `dlos_dp` 的数据接口和官方 DP 不一致 | `train_dlos.py` 里把 `batch["obs"]` 当成官方 obs dict，但旧 `dataset.py` 实际返回单 tensor，且缺少 `agent_pos` | `v3.5` 原型代码沿用了自定义 image-only 数据流，没有严格对齐官方 Push-T image baseline | 重写 `dlos_dp/dataset.py`，让其返回 `obs["image"]`、`obs["agent_pos"]`、`action` 和 `obs_next_image`，并复用官方 `ReplayBuffer/SequenceSampler/Normalizer` 语义 | `Stage 1` 可以在官方 `DiffusionUnetHybridImagePolicy` 上直接接入 DLOS loss |
| 20 | `dlos_dp` 图像维度假设错误 | DINO 编码与官方视觉栈前置处理可能收到错误维度的图像 | Push-T zarr 中 `img` 实际是 `HWC`，而 v3.5 原型代码按 `CHW` 直接使用 | 在 `dlos_dp/dataset.py` 和 `stage0_wm_probe.py` 中统一做 `HWC -> CHW`，并在 dataset 内完成 `/255` 归一化 | `obs["image"]` 和 `obs_next_image` 均与官方 DP 视觉接口对齐 |
| 21 | `torch.hub` 直连 DINOv2 不稳定 | WSL 下经常因为 GitHub / hub 拉取失败而卡住 `FrozenDINOv2Encoder` | `torch.hub.load("facebookresearch/dinov2", ...)` 对当前网络环境不稳定 | 下载本地 DINOv2 仓库与权重到 `d:\\Code\\Learning\\EI\\_cache`，并让 `dino_encoder.py` 优先走本地 repo + 本地权重 | `FrozenDINOv2Encoder` 可稳定离线加载 |
| 22 | `stage0_wm_probe.py` 在 smoke 截断编码时越界 | `IndexError: index ... is out of bounds` | 只编码了前几批 frame，但仍按全量 `actions/episode_ends` 构建 transition | 给 `stage0_wm_probe.py` 增加“只保留完整 episode”的截断逻辑，并让 partial smoke cache 单独命名，避免污染 full cache | `Stage 0 smoke` 已通过，可进一步运行 full probe |
| 23 | `v3.5` group 语义与文档描述不完全一致 | `group C` / `group E` 在早期草稿里容易退化成相近路径 | 原型代码没有把 `final-x0` 与 `intermediate-x0 + stop-grad` 清晰区分 | 在 `dlos_loss.py` 中显式区分：`C=final_x0`，`D=intermediate x0_hat`，`E=intermediate x0_hat + stop-grad`，并同步更新 `stage1_generate_cmds.py` 说明 | `A/B/C/D/E` 五组现在可按文档定义进行首轮消融 |
