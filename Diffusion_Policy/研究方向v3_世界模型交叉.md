# Diffusion Policy 研究方向 v3 — 世界模型交叉方向

## 为什么需要 v3

v2 的主线方向（Curriculum-Driven Data-Efficient DP）在实验中遇到了预期内的风险：

**easy-to-hard + difficulty_score_mean 没有赢过 random baseline。**

这个结果说明：

- Diffusion Policy 是监督式行为克隆，训练本质上是回归任务
- SGD 对数据呈现顺序**不敏感** — 这与 RL 中 curriculum 有效的机制完全不同
- RL 中 curriculum 有效是因为它影响**探索分布**；BC 中数据顺序不影响最终梯度期望

**课程排序改变的是"数据怎么被看到"，而 BC 需要的是"从数据中提取更多信号"。**

因此我们需要转向一个不依赖数据顺序，而是改变**模型从数据中学到什么**的方向。

### 发现的空白

所有 World Model × DP 工作都在做"**重型世界模型**" — 要么是 video diffusion，要么是完整的 state-space model。

**没有人做过"最轻量的世界模型辅助 DP 训练"** — 即在标准 DP 训练中加一个极小的辅助 dynamics loss，不改架构，不单独训练世界模型。

## 新主线方向：Latent Dynamics-Regularized Diffusion Policy

### 一句话题目

**Dynamics-Aware Diffusion Policy: Lightweight Latent World Model as Training Regularizer**

动态感知扩散策略：轻量潜空间世界模型作为训练正则化器

### 核心想法

标准 Diffusion Policy 的训练目标是纯回归式的：

```
obs → action    (去噪损失)
```

模型只学"看到什么做什么"，不理解"做了之后世界会怎样变"。我们加一个极轻量的辅助任务：

```
主任务: obs_t → action_t                        (标准 diffusion 去噪损失)
辅助任务: f(obs_t) + action_t → f(obs_{t+1})    (latent dynamics 预测损失)
```

其中 `f()` 是冻结的 DINOv2-small 编码器。辅助任务只是一个小 MLP：

```
DINOv2(obs_t) ──┐
                 ├──→ [MLP dynamics head] ──→ predicted DINOv2(obs_{t+1})
action_t ────────┘                                    ↕ (L2 loss)
                                              actual DINOv2(obs_{t+1})
```

**这是"世界模型"的最小化实例** — 不预测像素，不预测视频，只在冻结的视觉特征空间里预测下一帧的 embedding。

### 为什么这是新的

| 现有工作 | 与我们的关键区别 |
|---|---|
| CLaD (2026-03) | 完整架构重设计（0.66B参数、EMA target encoder、cross-attention）；我们只在标准 DP 上加一个 MLP head |
| GPC (2025-02) | 训练完整视频世界模型用于规划；我们不训练独立世界模型 |
| DiWA (2025-08) | 在世界模型内做 RL 微调；我们不做 RL |
| "Robots Pre-Train Robots" (ICLR 2025) | 用 dynamics alignment 做**编码器预训练**；我们做 **DP 训练时的辅助损失** |
| DynaGuide (NeurIPS 2025) | 训练 dynamics model 用于**测试时 guidance**；我们用于**训练时正则化** |
| UWM (2025-04) | 统一 video + action diffusion 在单一 DiT 中；完全不同的架构 |
| **DAP (2025-10)** | 在 Flow Matching Policy 中集成 dynamics，**推理时**双向纠错；我们用 DDPM，dynamics **仅训练时**起作用，推理时丢弃 |
| **LDA-1B (2026-02)** | 1B 参数基座模型，在 DINO latent space 做 dynamics + action diffusion，需 30K 小时数据；我们只加 200K MLP，不需额外数据 |

**核心差异**：所有现有工作要么把世界模型做成**独立组件**（重），要么把它融入**全新架构**（重设计），要么做成基座模型（重数据）。我们的做法是**在现有 DP 架构上只加一个辅助损失** — 不改主网络，不改推理流程，只在训练时起正则化作用。

**关于 LDA-1B 的特别说明**：LDA-1B 与我们共享"在 DINO latent space 做 dynamics 预测"这一技术前提，但定位完全不同。LDA-1B 是 1B 参数的基座模型路线（需要 30K 小时异构数据 + multi-modal DiT），我们是在标准 DP 上做最小改动的正则化器（200K MLP + 现有 demo 数据）。LDA-1B 的成功反而为我们提供了间接背书：DINO latent space 确实适合做 dynamics 预测。

### 为什么它应该有效

1. **解决 BC 的根本问题**：BC 只学 obs→action 映射，不学因果关系。辅助 dynamics loss 迫使 encoder 学到 dynamics-aware 特征
2. **正则化效果**：在少样本场景下，额外的自监督信号防止过拟合
3. **信息免费**：`obs_{t+1}` 就在训练数据里，不需要额外标注
4. **与课程的关键区别**：课程改变"数据怎么被看到"（对 BC 无效）；dynamics loss 改变"模型从数据中学到什么"（直接影响表征质量）

### 论文故事线

**从课程失败到 dynamics awareness 的自然转折：**

1. **出发点**：DP 在少样本下性能退化严重
2. **尝试 1**：课程排序（v2 方向）→ negative result，说明数据顺序对 BC 无效
3. **分析**：问题不在于数据呈现方式，而在于模型从有限数据中提取信息的效率
4. **方案**：加入轻量辅助 dynamics loss，让模型不只学 "what to do"，还学 "what happens next"
5. **结果**：（假设）在 10/25/50 demo 下，dynamics-aware DP 比标准 DP 有明显提升

**这个故事线非常干净**：negative result（课程无效）自然引出 positive result（dynamics 有效），有对照、有分析、有解释。

### 技术细节

#### Dynamics Head 架构

```python
class LatentDynamicsHead(nn.Module):
    def __init__(self, obs_dim=384, action_dim=2, hidden=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(obs_dim + action_dim, hidden),
            nn.ReLU(),
            nn.Linear(hidden, hidden),
            nn.ReLU(),
            nn.Linear(hidden, obs_dim),
        )
    
    def forward(self, obs_embed, action):
        x = torch.cat([obs_embed, action], dim=-1)
        return self.net(x)
```

- obs_dim = 384（DINOv2-small 的 CLS token 维度）
- 参数量：~200K（相比 DP 主网络的 ~20M 可忽略不计）
- VRAM 增加：<50MB

#### 训练损失

```python
total_loss = diffusion_loss + lambda_dyn * dynamics_loss
```

- `diffusion_loss`：标准 DDPM 去噪损失
- `dynamics_loss`：L2 loss between predicted and actual next-frame DINOv2 embedding
- `lambda_dyn`：权重超参数（建议从 0.1 开始搜索）

#### 不改推理

训练完成后，dynamics head 可以丢弃。推理流程完全不变。

可选：保留 dynamics head 用于测试时 self-verification（预测 vs 实际 embedding 偏差作为异常信号）。

### 适合我们配置的原因

| 约束 | 满足情况 |
|---|---|
| RTX 5070 Laptop 8GB | DINOv2-small 冻结 ~300MB + DP ~4GB + dynamics MLP ~50MB = ~4.5GB，充足 |
| 无真机 | 全部仿真 |
| 工程复杂度 | 只加一个 MLP + 一个 loss term，不改主网络 |
| 论文味 | 有清晰 research question + 从负结果自然引出 + World Model 交叉 |

### 风险与降风险

| 风险 | 概率 | 降风险 |
|---|---|---|
| DINOv2 embedding 的 dynamics 不够平滑，MLP 难学 | 中 | 1) 先验证 dynamics MLP 单独在全量数据上的预测误差；2) 如果 CLS token 不好，试 patch token 平均 |
| 辅助损失干扰主任务收敛 | 中低 | lambda_dyn 从小值开始，做超参扫描 |
| 少样本下 dynamics loss 也过拟合 | 中 | 1) DINOv2 冻结已提供强先验；2) dynamics head 很小，过拟合风险低 |
| 效果不如直接用 DINOv2 backbone 的提升大 | 中 | 关键消融：Baseline-DINO vs Ours，隔离 dynamics 的增量贡献 |

### 与 v2 课程实验的关系

课程实验不是浪费 — 它变成了 **论文的第一组实验**：

1. Section 4.1: "Does data ordering matter for DP?" → **No**（课程实验的 negative result）
2. Section 4.2: "What if we change what the model learns instead?" → **Yes**（dynamics-aware DP 的 positive result）

这个 **对比结构** 让论文更有说服力。

## 备选方向：VLM-Guided Demonstration Curation for DP

### 核心想法

不改模型，改数据：用小型 VLM（如 Qwen2-VL-2B）对示教质量打分，然后加权/过滤训练数据。

### 竞品

| 工作 | 区别 |
|---|---|
| QoQ (2026-03) | 用 influence function 打分（梯度计算密集）；我们用 VLM 打分（zero-shot） |
| Demo-SCORE (2025-03) | 用在线 rollout 评估；我们用离线 VLM 评估 |

### 为什么是备选不是主线

1. VLM 在 Push-T 这种简单场景可能提供不了有意义的质量信号
2. 运行 2B VLM 推理仍需 ~5GB VRAM，加上 DP 训练可能紧张
3. "用 VLM 打分"的创新点比 "dynamics-aware training" 弱

### 但可以作为后续增强

如果主线 dynamics-aware DP 有效，可以加一步：用 dynamics prediction error 本身作为数据质量信号（预测误差大 = 示教质量差或数据难度高）。

## 执行路径

### Stage 1：验证 dynamics 可学性（1-2 天）

在 Push-T 全量数据上：
1. 用 DINOv2-small 提取所有 observation 的 embedding
2. 训练一个独立 dynamics MLP：`(embed_t, action_t) → embed_{t+1}`
3. 看 L2 prediction error 能否收敛到低值

**如果连独立 dynamics MLP 都学不好，这条路就不用走了。**

### Stage 2：接入 DP 训练（2-3 天）

1. 在现有 DP 训练代码中加入 DINOv2 embedding 提取
2. 加入 dynamics head 和辅助损失
3. 在 Push-T full demo 下对比：Baseline-R18 vs Baseline-DINO vs Ours

### Stage 3：少样本验证（3-5 天）

1. 在 50 / 25 / 10 demo 下重复 Stage 2 实验
2. 画 demo count vs test score 曲线
3. 分析 dynamics loss 在不同数据量下的增益趋势

### Stage 4（可选）：扩展到 LIBERO

只有 Stage 3 有明确正向信号才进行。
