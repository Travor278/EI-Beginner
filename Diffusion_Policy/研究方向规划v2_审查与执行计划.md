# Curriculum Training for DP 审查与执行计划

## 结论

`Curriculum Training for DP` 是一个值得继续推进的方向，而且比我们上一版里那些 `test-time guidance / memory / verifier` 方向更不拥挤。

但它现在最需要的不是继续扩题，而是先把问题收窄成一个能被当前机器和时间预算验证的核心假设：

**在小样本示教下，基于示教难度的课程式训练，是否能稳定提升 Diffusion Policy 的样本效率和长时程成功率？**

这条主线是可做的，适合当前 `8GB` 显存和仿真条件；不过文档里有几处表述和实验设计需要收口，否则很容易在后面掉进“大矩阵跑不完、结果也解释不清”的坑里。

## 当前版本最强的地方

1. 赛道切换是对的。
   从拥挤的 `test-time / training-free / adaptive inference` 转到训练侧，是合理转向。

2. 主问题够聚焦。
   `Curriculum + data efficiency` 这两个关键词能自然串成一个研究故事，不像很多“加一个模块再加一个模块”的方向那么散。

3. 资源匹配度高。
   `Push-T` 上先做课程排序和少样本实验，完全适合当前 `robodiff-gpu` 环境和你的机器。

4. 可扩展性好。
   如果基础结果成立，后面既能接 `DINOv2`，也能接失败分析，故事线很顺。

## 必须先修正的地方

### 1. 不要把“无直接竞品”写得太满

现在 `v2` 里多次把这个方向写成“确认空白”“无直接竞品”。这在内部规划里可以保留为工作假设，但在真正做实验前，最好改成更稳的表述：

- `Curriculum ordering for Diffusion Policy training is under-explored`
- `We do not find a close prior work that studies difficulty-ordered imitation training for DP`

更稳的原因不是保守，而是这个方向有很多邻近工作会被审稿人拉进来比较：

- curriculum learning in RL
- data ordering / sample weighting in supervised learning
- diffusion training acceleration
- data-efficient imitation learning

所以建议把贡献写成：

`首次系统研究课程排序在 Diffusion Policy 模仿学习中的作用`

而不是：

`首次提出课程训练 DP`

### 2. “难度”定义还不够扎实

现在文档里把难度候选列得很多，但还没有分清：

- `task difficulty`
- `trajectory complexity`
- `demo quality`
- `state distribution rarity`

这四个概念很容易混在一起。

如果一开始就把长度、方差、曲率、多模态、回放成功率全上了，最后很可能出现：

- 指标彼此冲突
- 课程顺序不稳定
- 结果显著性不够
- 解释不清到底是“难度”起作用，还是“低质量样本过滤”起作用

更稳的做法是第一阶段只保留两类：

1. `trajectory length`
2. `action variance`

这两个指标实现成本最低，也最容易先做出一个能讲清楚的最小故事。

### 3. DINOv2 不应该一开始就是主贡献的一半

`Curriculum + DINOv2` 是一个不错的二阶段增强版，但不该在第一轮就绑死。

原因很简单：

- 如果课程本身没信号，DINOv2 只会让问题更难定位
- 如果 DINOv2 有域差问题，容易把课程效果盖住
- 你当前最大价值是先证明“课程排序本身有效”

所以更合理的故事顺序应该是：

1. 先证明 `curriculum` 对 `ResNet baseline DP` 有效
2. 再证明 `frozen pretrained encoder` 是否进一步放大这个效果

### 4. 当前实验矩阵还是偏大

文档里的完整矩阵是：

`(backbone) x (curriculum) x (demo count) x (task)`

这在论文里很好看，但作为第一阶段执行计划太大了。

更现实的第一轮应该压成：

- task: `Push-T`
- backbone: `ResNet-18`
- curriculum: `random / easy-to-hard / hard-to-easy`
- demo count: `full / 50 / 10`
- seed: `2`

先用这个最小矩阵判断：

- 课程效果到底有没有
- 信号是在低数据最明显，还是根本不稳定
- 哪个难度指标最靠谱

只有这个结果成立，才值得上 `DINOv2` 和 `LIBERO`

## 我对可做性的判断

### 结论

`可做，而且值得做。`

但我会把它定义成：

`中等创新风险，低到中等工程风险，低算力友好`

### 为什么我认为可做

1. 你现在的算力更适合“训练协议创新”，而不是“大模型或重推理创新”。
2. curriculum 的改动主要在数据组织和训练调度，和当前环境兼容度高。
3. 即使第一版效果不大，也容易转成：
   - negative result with analysis
   - 哪种难度度量有效/无效的系统比较
   - failure-driven curriculum 的后续版本

### 最大的不确定性

最大的不确定性不是实现，而是：

**DP 对样本顺序到底有多敏感。**

如果它本质上对 shuffle 不太敏感，那么课程收益可能只在极少数据或长时程任务上出现。这也是为什么我们必须把实验先压缩到能快速判定“有没有信号”的最小集。

## 我建议保留的最终主线

### 主线

`Curriculum-Driven Data-Efficient Diffusion Policy`

### 一阶段增强

`Curriculum + frozen pretrained encoder`

### 二阶段增强

`Failure-driven curriculum`

也就是说，我们现在不要把主线写成一个一次做完的巨型项目，而是写成一个三级递进结构：

1. 先验证课程排序
2. 再看预训练视觉特征是否放大收益
3. 最后再把失败分析作为课程设计来源

第一轮只回答两个问题：

1. curriculum 有没有稳定信号

### Stage E：设一个是否升级的门槛

只有满足下面任意一个条件，才进入 `DINOv2` 阶段：

1. 在 `50` 或 `10` demo 下，`easy_to_hard` 明显优于 `random`
2. 课程效果在长 rollout 或 late-stage success 上更明显
3. 两个 seeds 的趋势一致

如果第一轮没有信号，就不要急着加 DINOv2，而是先做：

- 重新审视难度定义
- 看是否需要加入 `anti-curriculum` 或 `mixed curriculum`
- 检查是否任务本身过于简单
